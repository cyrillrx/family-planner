## Context

Personal project, built for one group — which may be a single person, two adults, or a whole
family. Several devices per group have to stay in sync.

Low cognitive load is a hard requirement: simple interfaces, explicit instructions, decisions
already made by the time someone opens the app. The app has to be usable when attention is scarce.

---

## Modules

### 1. Meal — Meal planner
- Weekly meal plan generated by AI (Claude API), validated manually
- Recipes stored locally (SQLDelight), manual entry + AI enrichment
- Shared grocery list synced in real time (Firestore): auto items (from menu) + manual
- 2 Telegram notifications per cooking day: morning (preview) + evening (step-by-step recipe)
- Meals can be locked (not overwritten on re-generation)

### 2. Events — Family events
- Recurring events: kids' sports, adult sports, weekly activities
- One-off events: birthdays, appointments, parties
- Configurable Telegram reminders (D-7, D-1, morning of the day)
- Shared across the group in real time

### 3. Tasks — Shared to-do list
- Shared tasks: errands, repairs, admin, household chores, etc.
- Add, complete and delete synced in real time
- No priority or assignee in V1 — flat shared list

## Data model

### Firestore (real-time sync — shared across the group's devices)

```
weekPlan/{weekId}/days/{dayId}
  recipe_id    : String
  locked       : Boolean
  meal_slot    : DINNER             # LUNCH added in V2

groceryItems/{itemId}
  name         : String
  checked      : Boolean
  source       : AUTO | MANUAL
  ingredient_id: String?
  quantity     : String?

events/{eventId}
  title         : String
  date          : Timestamp
  recurrence    : NONE | WEEKLY | MONTHLY
  recurrence_day: Int?              # 0=Monday … 6=Sunday
  reminder_days : List<Int>         # e.g. [7, 1, 0]
  notes         : String?

tasks/{taskId}
  title      : String
  done       : Boolean
  created_at : Timestamp
  created_by : String               # Firebase uid
```

### SQLDelight (local — recipes and config)

```
Recipe
  id            TEXT PRIMARY KEY
  name          TEXT NOT NULL
  tags          TEXT                -- JSON array
  duration_min  INTEGER
  servings      INTEGER
  steps         TEXT                -- JSON array
  last_cooked   TEXT?               -- ISO date

Ingredient
  id            TEXT PRIMARY KEY
  name          TEXT NOT NULL
  category      TEXT

RecipeIngredient
  recipe_id     TEXT REFERENCES Recipe(id)
  ingredient_id TEXT REFERENCES Ingredient(id)
  quantity      REAL
  unit          TEXT
```

## Telegram notifications

Orchestrated by **Claude Code Routines** (included in Pro/Max Anthropic plan).

### Configured triggers

```yaml
# notify_morning.py
cron: "0 8 * * 2,4"     # Tuesday and Thursday at 8am

# notify_evening.py
cron: "0 17 * * 2,4"    # Tuesday and Thursday at 5pm
```

Cooking days are configurable in the app (Settings → Cooking days).

### Required environment variables

```
FIRESTORE_TOKEN        # Firebase service account
TELEGRAM_BOT_TOKEN     # Bot token from @BotFather
TELEGRAM_CHAT_ID       # Family Telegram group ID
ANTHROPIC_API_KEY      # For contextual message generation
```

### Fallback

If Claude Code Routines are unavailable (research preview) → same Python scripts on Raspberry Pi with system cron. No code changes required.

## Design constraints

- All decisions must be **already made** by the time someone checks the app or Telegram
- **Zero friction**: Telegram notifications must be enough to cook without opening the app
- Recipe preparation time: **≤ 30 min**
- Simple interface, clear instructions — designed for use under high cognitive load
